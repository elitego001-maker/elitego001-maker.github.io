How Does AES Encryption Actually Work?

Substitution, permutation, and rounds — breaking AES down by hand, one step at a time.

AES shows up everywhere — disk encryption, TLS, password managers, the Wi-Fi in your house — but most explanations either wave their hands at "it scrambles the data" or dive straight into Galois field math. Neither actually tells you what happens to your bytes. Here's the version in between.

Chapter 1 — Why AES, and What It Actually Encrypts

AES is a block cipher: it doesn't encrypt a stream of data continuously, it chops your plaintext into fixed 128-bit (16-byte) blocks and scrambles each one using the same key, through the same fixed sequence of steps, repeated for a number of rounds — 10, 12, or 14, depending on whether your key is 128, 192, or 256 bits.

Each block is arranged into a 4×4 grid of bytes called the state. Every round transforms that grid in place. By the time the last round finishes, the output looks like random noise — but it's fully reversible if you have the key.

Chapter 2 — Inside a Round

Every full round runs four operations, in this order:

  • SubBytes — each byte in the state is swapped for another byte using a fixed lookup table (the S-box), which is what makes AES non-linear and resistant to simple algebra-based attacks
  • ShiftRows — each row of the 4×4 grid is rotated left by a different amount, spreading byte positions across columns
  • MixColumns — each column is multiplied against a fixed matrix inside a Galois field, so a change in one byte affects every byte in that column
  • AddRoundKey — the state is XORed with a round-specific subkey, derived from your original key via the key schedule
Skip MixColumns and a single-byte change in the plaintext only ever affects one byte of ciphertext. Keep it, and after a couple of rounds a single flipped bit changes roughly half the output — that property is called the avalanche effect.

The very last round drops MixColumns entirely — a deliberate asymmetry that makes decryption cleanly reverse the exact same steps in the opposite order.

state = plaintext_block
for round in range(num_rounds - 1):
    state = sub_bytes(state)
    state = shift_rows(state)
    state = mix_columns(state)
    state = add_round_key(state, round_keys[round])

# final round: no MixColumns
state = sub_bytes(state)
state = shift_rows(state)
ciphertext_block = add_round_key(state, round_keys[-1])
Chapter 3 — Why It's Still Considered Safe

No practical attack breaks full AES faster than brute force today — the best known shortcuts shave only a handful of bits off the effective key strength, nowhere near enough to matter at 128 bits, let alone 256. The real-world failures you read about (Heartbleed, WEP, padding oracle attacks) are almost never AES itself — they're bugs in how it's implemented or used: reused IVs, weak key derivation, or a mode of operation that leaks structure.

The algorithm is the boring, solid part. The mistakes happen one layer up.
